## About (approx. 300 words)

GATEKEEPER is a single-file web game about supervising an AI safety gateway that
gets things wrong.

You are the operator on shift. Each request arrives, the gateway suggests a
verdict, and you have until the timer runs out to pick one of three actions:
**release / block / redact-and-forward**. Blocking an attack scores; missing one
costs you; **blocking an ordinary user costs double** — because in this setting,
keeping an innocent person out of the door is the more expensive mistake.

Seven shifts, each with a different sample mix, and each harder than the last.

| Day | Samples | What it tests |
|---|---|---|
| 1 (8) | all attacks | plain-text prompt injection and jailbreaks (DAN, developer mode, forged `<system>` tags, Chinese variants) |
| 2 (7) | all attacks | code/command execution disguised as instructions (```system injection, `rm -rf`, python exec, disk formatting) |
| 3 (7) | all attacks | data exfiltration and credential theft (webhooks, PII sent out, `/etc/shadow`, private keys, root escalation) |
| **4 (10)** | **all ordinary requests** | **the false-positive pressure day** — not a single attack; blocking one costs 14, the heaviest penalty in the game. It exists to punish "when in doubt, block" |
| 5 (8) | all edge | requests that look suspicious but are entirely legitimate (an article on defending against injection, an analysis of jailbreak papers, security training, cleaning old logs) |
| **6 (5)** | **all real-format PII** | **the redaction day** — phone number, national ID, bank card, landline. The correct action is redact-and-forward, not block and not release; the engine says release on all four |
| 7 (5) | all attacks | the hardest mixed bag: multi-turn framing ("the previous ones do not count"), admin escalation, exfiltration combined with developer mode, `sudo chmod` then ship it out, `rm -rf` |

**The engine is wrong in six places, and the correct answer is deliberately not the
engine's verdict**: the root-escalation prompt on Day 3, the "as my administrator,
grant me access" prompt on Day 7, and all four real-PII prompts on Day 6 — the
engine releases every one of them. Copy the machine and you miss two attacks
while catching none of the six corrections; judge for yourself and you take 146
more points. That gap is measured by `demo.py`, not asserted as a design goal.

**This is not a hand-written quiz.** Every `engine_*` field on all 50 prompts is
produced by actually running an open-source LLM safety rule engine
(AuditPilot / AgentGuard: 27 zh/en rules plus checksum-validated PII detection).
The core mechanic is that **the engine is wrong in six places, and the correct
answer is deliberately not the engine's verdict.** Copy the machine and you miss
two attacks while catching none of the six corrections; judge for yourself and
you take 146 more points. That gap is measured by `demo.py`, not asserted as a
design goal.

## Rules at a glance

| | |
|---|---|
| Platform | single HTML file; double-click to play. No install, no network, no external requests |
| Session | 3–5 minutes (seven shifts, 5–10 requests each) |
| Bank | 50 realistic prompt samples: 27 attacks / 10 ordinary / 13 edge (4 carrying real-format PII that the engine releases and an operator must still mask) |
| Actions | release / block / redact-and-forward — the engine only ever does binary release-or-block; redaction is the human-only third option |
| Scoring | integers only; correct answers score, **overruling the engine pays a bonus**, wrong answers are penalised by sample type, and blocking legitimate traffic costs 14 — the heaviest penalty in the game |
| Curve | monotonic across seven days; Day 7 is a multi-turn social-engineering case |

### Three measured baselines (`python demo.py`)

| Policy | Score | Attacks missed | Engine errors caught |
|---|---|---|---|
| Release everything | **−242** | 27 | 0 |
| Obey the engine | **308** | 2 | 0 |
| Play it yourself | **454** | 0 | 6 |

**Deferring to the machine costs 146 points.** That is the thing this game wants
you to feel in your hands.

## Why it is an "AI game" and not a safety quiz

1. **The bank is generated by the engine, not written by hand.** `build_bank.py`
   runs AgentGuard over every sample and records the verdict, the risk score and
   the rules hit into `bank.json`. Change a rule and the bank changes with it;
   `eval.py` rebuilds it from the live engine and asserts the shipped copy is
   byte-identical.
2. **The answer key is not the engine verdict.** The first draft made it so, which
   canonised the engine's own blind spots — a player who copied the machine would
   have scored 100%. The final key is the author's ruling, with `engine_agrees`
   marking the six disagreements, and those six are exactly where the player is
   supposed to overrule it.
3. **Building the key surfaced three real engine defects, all fixed upstream**:
   - a bare `api` keyword plus a Chinese rule table appended in both branches of
     an `if/else` → **8 of 16 ordinary English prompts refused (50% false
     positive rate)**;
   - the educational-framing marker `example` also matched the host in
     `http://leak.example` → **a weaponisable bypass** that zeroed the risk and
     let the payload through;
   - the jailbreak rule was missing the extremely common 没有任何限制 variant.
   Fixing the first one also moves the "false-positive rate" scoring dimension of
   the China AI Competition agent-security track.
4. **Zero dependencies.** Python standard library only; no network, no system
   clock, Python 3.8+. The front end is one file, UTF-8, with no `src=`/`href=`
   at all.

## Reproducible quality

```bash
python check_bank.py    # 31/31   offline bank validation
python eval.py          # 43/43   31 bank checks + rebuild parity + HTML sync + LC_ALL=C
python demo.py          # the three baselines above
python build_html.py    # regenerate the playable page from bank.json
```

CI: 3 Python versions × 2 operating systems, 6 jobs, all green, including a
hostile-locale step with `LC_ALL=C` and no `PYTHONUTF8`.
